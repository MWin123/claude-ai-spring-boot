# Lombok Rules

**Default: modern Java.** Use a **record** wherever one fits. Use Lombok only for plain boilerplate a record cannot replace: `@Slf4j` for every logger, `@RequiredArgsConstructor` for constructor injection (even with a single dependency), `@Getter`/`@Setter` on mutable classes, `@Builder` where many optional parameters justify it. On JPA entities use only the safe Lombok subset below.

| Class type | Approach |
|------------|----------|
| Non-API DTOs, events, immutable config properties, value objects | **Record** (no Lombok); API models are generated |
| Services, components, controllers, filters, configuration classes | Lombok: `@RequiredArgsConstructor` (constructor injection), `@Slf4j` (logger) |
| Mutable non-entity classes (state holders, test data) | Lombok: `@Getter`/`@Setter`, `@Builder` where useful |
| `@Entity`, `@Embeddable`, `@MappedSuperclass` | Safe subset only: `@Getter`, `@Setter`, `@NoArgsConstructor(access = PROTECTED)`, `@Builder` on a constructor (business fields only); `equals`/`hashCode` written by hand |

```java
@Service
@Slf4j
@RequiredArgsConstructor
@Transactional(readOnly = true)
public class OrderService {
    private final OrderRepository repo;   // constructor generated by Lombok

    public OrderSummary get(Long id) {
        log.info("Loading order {}", id);
        return repo.findById(id).map(OrderSummary::from).orElseThrow();
    }
}

public record OrderSummary(Long id, String status) {   // record, not Lombok
    static OrderSummary from(Order o) { return new OrderSummary(o.getId(), o.getStatus()); }
}
```

## Lombok on entities: safe subset
```java
@Entity
@Getter
@Setter
@NoArgsConstructor(access = AccessLevel.PROTECTED)  // required by JPA
public class Product {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    @Setter(AccessLevel.NONE)                       // never overwrite the id
    private Long id;
    private String name;

    private boolean active = true;                  // default applies to every constructor

    @Builder                                        // on the constructor: business fields only, no id/version
    public Product(String name) {
        this.name = name;
    }

    // equals/hashCode written by hand, based on the identifier; use getters and
    // Hibernate.getClass() so lazy proxies compare equal to the loaded entity
    @Override public boolean equals(Object o) {
        return this == o || o instanceof Product p && getId() != null && getId().equals(p.getId());
    }
    @Override public int hashCode() { return Hibernate.getClass(this).hashCode(); }
}
```

**Allowed on entities:** `@Getter`, `@Setter`, `@NoArgsConstructor` (use `AccessLevel.PROTECTED`), `@Builder` on a constructor.

**Never on entities:**
- `@Data`, `@EqualsAndHashCode`: generated `equals`/`hashCode` use mutable and lazy fields, which breaks `Set` semantics and Hibernate proxies; the id is `null` before persist
- `@ToString`: triggers lazy loading and infinite recursion on bidirectional associations
- `@Value`: makes the class immutable and final, which JPA/Hibernate proxies cannot handle

**Rules**
- Put `@Builder` on a constructor with the business fields only, never on the entity class: a class-level `@Builder` (with the `@AllArgsConstructor` it needs next to `@NoArgsConstructor`) exposes `id`/`version`, so `Product.builder().id(5L)` bypasses the `@Setter(AccessLevel.NONE)` guard
- Fields with initializers (`= true`, `= new ArrayList<>()`) keep their defaults, since the constructor does not assign them; no `@Builder.Default` needed
- Tests set a generated id with `ReflectionTestUtils.setField(entity, "id", 1L)` instead of a setter
- Write `equals`/`hashCode` by hand, id-based, via `getId()` and `Hibernate.getClass(this)` (never direct field access or `getClass()`, both break on proxies)
- Avoid `@SneakyThrows` and `@Cleanup` (use proper exception handling and try-with-resources)

## Setup (Maven)
```xml
<dependency>
    <groupId>org.projectlombok</groupId>
    <artifactId>lombok</artifactId>
    <optional>true</optional>   <!-- version managed by the Spring Boot parent -->
</dependency>
```
- On JDK 23+ declare Lombok in `maven-compiler-plugin` under `annotationProcessorPaths`; annotation processing is no longer enabled implicitly

## Setup (Gradle)
```kotlin
dependencies {
    compileOnly("org.projectlombok:lombok")          // version from the io.spring.dependency-management plugin
    annotationProcessor("org.projectlombok:lombok")
    testCompileOnly("org.projectlombok:lombok")      // only if tests use Lombok
    testAnnotationProcessor("org.projectlombok:lombok")
}
```
